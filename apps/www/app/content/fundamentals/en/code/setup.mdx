Follow these steps to get started with using Designsystemet in code for the first time.

## 1. Install the packages
Designsystemet consists of several code packages that you can freely choose from, depending on your needs and preferences. You can use the packages together, or pick only the parts that speed you up, while keeping the freedom to code things yourself where you want to.

We recommend starting with `@digdir/designsystemet-web` and `@digdir/designsystemet-css`. You can also use `@digdir/designsystemet-web` without `@digdir/designsystemet-css` if you already have your own styling, or use only the CSS package if you handle interactivity yourself.

<Alert data-color='info'>

<h3 className="ds-heading" data-size='xs'>Note: `background` and `color` are set on `<body>`</h3>

`background` and `color` are automatically defined on the `body` element and where `data-color-scheme` is set. 
This is to ensure [universal design (w3.org)](https://www.w3.org/WAI/WCAG21/Understanding/resize-text.html) and consistent font and color across the application.
This can be easily overridden in your own theme or in your global CSS file.

</Alert>


## 4. Import the theme

The Designsystemet is designed to be themable, so it is important to import your theme after importing `@digdir/designsystemet-css`.

[Build your own theme](/en/fundamentals/start-here/own-theme) or use the default theme; `@digdir/designsystemet-css/theme`.

## 5. Usage

You are now ready to use the Designsystemet in code! 


All components have their own page in the [component documentation](/en/components), we recommend that you read through these to see how you can use the components.

It is also recommended that you read through the accessibility page.

- Use `data-color-scheme="light | dark | auto"` to set dark/light mode.
  - corresponds with `Appearance › Color scheme` in Figma
- Use `data-size="sm | md | lg"` to set the size of the components.
  - corresponds with `Appearance › Size` in Figma
- Use `data-color` to set the color of the components.
  - corresponds to `Appearance › Color` in Figma

## Typescript

Designsystemet provides type safety for its data attributes.

Install the type package and add the type files to `tsconfig.json` to access them.

```sh
npm i -D @digdir/designsystemet-types
```

## Font

The components are designed and developed with the [Inter font (github.com)](https://github.com/rsms/inter), so variations may occur if you use a different font.
If you choose to install the font in a way other than altinncdn.no, remember to include the font weights `400`, `500`, and `600`.

### Text scaling that follows system settings

By default, most browsers scale text based on zoom and browser text settings, but not system settings.
To also [respect system settings](https://www.joshtumath.uk/posts/2026-07-02-lets-fix-the-webs-text-size/), add the following code in `<head>`:

```html
<meta name="text-scale" content="scale">
```

### Add the Inter font (optional)

Add the `<link>` tag below in the `<head>`, and set `font-family` to `Inter` in your global CSS file.

You can use this code to add the font in `<head>`:

```html
<link
  rel="stylesheet"
  href="https://altinncdn.no/fonts/inter/v4.1/inter.css"
  integrity="sha384-OcHzc/By/OPw9uJREawUCjP2inbOGKtKb4A/I2iXxmknUfog2H8Adx71tWVZRscD"
  crossorigin="anonymous"
/>
```
### Font configuration

We strongly recommend adding the following to your global CSS file.
`font-feature-settings` adds a tail to lowercase `l`s.

```css
body {
  font-family: var(--ds-font-family), sans-serif;
  font-feature-settings: 'cv05' 1; /* Enable lowercase l with tail */
}
```

## Testing

We aim for the components to function well across various test setups. Designsystemet is tested in JSDOM and HappyDOM, and through Playwright in Chromium, Firefox, and WebKit. However, there will always be frameworks, test environments, and meta-frameworks that handle asynchronous rendering or specific edge cases in different ways.

If you encounter issues with the design system in your test setup, we would very much like to hear about it. Please report them via a [GitHub issue](https://github.com/digdir/designsystemet/issues/new/choose) or ask us in [our open Slack](https://designsystemet.no/slack).

Note that not everything supported by browsers is implemented in environments with an artificial DOM, such as JSDOM and HappyDOM. You may need to add some configuration to your test setup:

<details className="ds-details">
<summary>HappyDOM setup</summary>

HappyDOM may require support for inheritance between `HTMLDocument` and `Document`:

```ts
// Polyfill missing HTMLDocument to Document inheritance in HappyDOM
if (
  typeof HTMLDocument !== 'undefined' &&
  !(HTMLDocument.prototype instanceof Document)
) {
  try {
    Object.setPrototypeOf(HTMLDocument.prototype, Document.prototype); 
  } catch (_) {}
}
```
</details>

<details className="ds-details">
<summary>JSDOM setup</summary>

JSDOM may lack support for certain methods on `HTMLDialogElement`:

```ts
// Polyfill missing HTMLDialogElement methods in JSDOM
if (typeof HTMLDialogElement.prototype.show !== 'function') {
  HTMLDialogElement.prototype.show = function () {
    this.open = true;
  };

  HTMLDialogElement.prototype.showModal = function () {
    this.open = true;
  };

  HTMLDialogElement.prototype.close = function (returnValue?: string) {
    this.open = false;
    if (returnValue !== undefined) this.returnValue = returnValue;
    this.dispatchEvent(new Event('close'));
  };
}
```
</details>
