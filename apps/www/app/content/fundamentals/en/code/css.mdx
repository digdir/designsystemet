## Layers

We use [css layers](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer) to get the lowest possible specificity in our css.
This means that you can easily override it with your own styling.

All our layers are under the layer group `ds`.

For example, if you have a css reset, this will override parts of what we have done. We recommend putting this in a layer and sorting this first.
You do this by first putting your reset in a layer, and then sorting this layer first:

```css
@layer my-reset, ds;
```

## Data attributes

We offer several data attributes that can be used to change the theme of the components.

### `data-color-scheme`

Used to change the color mode of the components. Possible values are `light`, `dark` and `auto`.

If `auto` is selected, the color mode will change based on the user's preferences using
[prefers-color-scheme](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-color-scheme).

You can read more about this at "[Colors in code](/en/fundamentals/code/colors)".

### `data-typography`

Used to change the typography of the components. Possible values ​​are `primary` and `secondary`.

A common use for this attribute is when you want a monospace font on tables.

Which typography is associated with `primary` or `secondary` must be defined in the team, using [Tokens Studio](https://tokens.studio/)
(with the Designsystemet design-tokens) or [Theme Builder](https://theme.designsystemet.no/en).

If you are going to use this attribute, you must remember to define `font-family` to use the `--ds-font-family` CSS variable.

This can be solved by, for example, using [attribute selector](https://developer.mozilla.org/en-US/docs/Web/CSS/Attribute_selectors) in CSS.

```html
<style>
[data-typography='secondary'] {
  font-family: var(--ds-font-family), monospace;
}
</style>
<table data-typography='secondary'>
…
</table>
```

## Helper classes

We use some helper classes that can be used more generally across components.

### `ds-sr-only`
Visually hides an element while still being accessible to screen readers.

### `ds-print-preserve`
Preserves appearance, including background color, in print.

### `ds-focus` / `ds-focus--inset`
Adds Designsystemet's focus ring around the element _when it gains focus with keyboard navigation_ (`:focus-visible`).

### `ds-focus--visible` / `ds-focus--visible--inset`
Static "always-on" classes that add Designsystemet's focus ring around the element. <span className='ds-focus--visible'>Example.</span>

## Tailwind CSS

<Alert data-color="warning">
Tailwind support is experimental. Which utilities are generated may change at any time, and will be communicated in the changelog.
</Alert>

Designsystemet's [command line tool](/en/fundamentals/code/cli-config) can generate a Tailwind theme file next to your regular theme CSS,
so Tailwind utilities use Designsystemet's design tokens instead of Tailwind's default scales.

Pass `--experimental-tailwind` to `tokens build`, or set `experimental_tailwind` on the `css` output in your config file.
For every `<theme>.css` you will then also get a `<theme>.tailwind.css`.

### Add the theme to Tailwind

Import the Tailwind theme file after `tailwindcss`. Designsystemet's CSS must be imported before `tailwindcss`,
so [Preflight](https://tailwindcss.com/docs/preflight) does not override our components.

<ds-tabs class="ds-tabs" data-wide-content>

```css

@import 'design-tokens-build/<your-theme>.css';

@import 'tailwindcss';
@import 'design-tokens-build/<your-theme>.tailwind.css';
```
  </ds-tabpanel>

```css
@import '@digdir/designsystemet-css/theme.css';

@import 'tailwindcss';
@import '@digdir/designsystemet-css/theme/designsystemet.tailwind.css';
```
  </ds-tabpanel>
</ds-tabs>

### What you get

The theme file maps design tokens onto Tailwind's [theme variable namespaces](https://tailwindcss.com/docs/theme#theme-variable-namespaces):

| Tokens | Namespace | Example |
| ------ | --------- | ------- |
| `--ds-color-*` | `--color-*` | `bg-accent-base-default`, `text-text-subtle`, `border-border-default` |
| `--ds-size-*` | `--spacing-*` | `p-4`, `gap-2`, `mt-6` |
| `--ds-border-radius-*` | `--radius-*` | `rounded-sm`, `rounded-md`, `rounded-lg`, `rounded-xl` |
| `--ds-shadow-*` | `--shadow-*` | `shadow-xs`, `shadow-sm`, `shadow-md`, `shadow-lg`, `shadow-xl` |
| `--ds-font-weight-*` | `--font-weight-*` | `font-regular`, `font-medium`, `font-semibold` |
| `--ds-opacity-*` | `--opacity-*` | `opacity-disabled` |
| `--ds-font-family` | `--font-sans` | `font-sans` |

Focus colours are not included, use the [`ds-focus` helper class](#ds-focus--ds-focus--inset) instead.

Values outside our scale still fall back to Tailwind's own, so `p-4` uses `--ds-size-4` while `p-16` uses Tailwind's default spacing scale.

### Data attributes

The theme file uses [`@theme inline`](https://tailwindcss.com/docs/theme#referencing-other-variables), which makes utilities
reference the `--ds-*` variables directly. That means our data attributes also change the Tailwind utilities:

```html
<div data-color="brand1" data-size="sm">
  <!-- background-color is brand1's base colour, and padding follows the small size mode -->
  <div class="bg-base-default p-4">…</div>
</div>
```

This works for `data-color`, `data-color-scheme` and `data-size`, on any element and at any depth.
