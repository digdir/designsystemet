Using a config file with the CLI gives you more control over your colours and makes it easier to update and maintain them.

## Getting Started

The config file can be named whatever you want, but if you use `designsystemet.config.json`, we will find it automatically when you run commands in the same folder.
You can place it anywhere in your project.

If you've placed your file in a different location or with a different name, you can use `--config <path>` in CLI commands.
Both `designsystemet.config.json` and `designsystemet.config.jsonc` are detected automatically, and both may contain comments and trailing commas.

```json
{
  "$schema": "node_modules/@digdir/designsystemet/dist/config.schema.json",
  "themes": {
    "my-theme": {
      "colors": {
        "primary": "#0062BA",
        "neutral": "#1E2B3C",
        "extra1": "#F45F63"
      },
      "borderRadius": 4
    }
  }
}
```

Above, we have defined a theme called `my-theme` with some colours and border radius.
Each colour is defined directly under `colors`, where the key is the colour's name and the value is a hex code.

## Running the CLI

Run the CLI in the same folder as your config file:

```bash
npx @digdir/designsystemet@latest
```

This creates CSS for all themes, based on the [`output`](#output) field in the config file. Type declarations and design tokens are only created if you add a `types` or `design-tokens` output.

| Option | Description |
| ------ | ----------- |
| `-c, --config <path>` | Path to the config file. |
| `--dry` | Dry run, no files will be written. |
| `--verbose` | Enable verbose output. |
| `--skip-check` | Skip the automatic migration check of the config file. |
| `-y, --yes` | Skip prompts, for example when migrating the config file. |

<Alert data-color="info">
The `tokens create` and `tokens build` commands are deprecated and will be removed in a future release. Use `designsystemet` with a config file instead.
</Alert>

## Structure

| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| $schema | String | No | Path to JSON schema for validation. Recommended: `node_modules/@digdir/designsystemet/dist/config.schema.json`. |
| output | Array | No | What the CLI should create, and where. Defaults to `["css"]`. See [Output](#output). |
| themes | Object | No | Contains all themes you want to define. Each key is the name of the theme. Required by outputs that are created from themes, see [Building without themes](#building-without-themes). |
| outDir | String | No | **Deprecated:** use `output[].dir` instead. |
| clean | Boolean | No | **Deprecated:** use `output[].cleanDir` instead. |

### Output

`output` is a list of what the CLI should create. Each item is either the name of an output type, which uses its default settings, or an object with custom settings.
Outputs are always created in the order `design-tokens`, `css`, `types`, whatever order they are listed in. When CSS and types are built from design tokens (with `tokensDir`), the design tokens must be created first.

All paths are relative to the config file.

```json
{
  "output": [
    { "type": "design-tokens", "dir": "./design-tokens" },
    { "type": "css", "dir": "./css", "tokensDir": "./design-tokens" },
    { "type": "types", "dir": "./types", "tokensDir": "./design-tokens" }
  ]
}
```

#### design-tokens

| Name | Type | Required | Default | Description |
| ---- | ---- | ------- | ------- | ----------- |
| type | `"design-tokens"` | Yes | | The output type. |
| dir | String | No | `designsystemet/design-tokens` | The folder where design tokens should be saved. |
| cleanDir | Boolean | No | `false` | Delete the files in the folder before creating design tokens. Removes files that are no longer in use. See [Cleaning](#cleaning). |

#### css

| Name | Type | Required | Default | Description |
| ---- | ---- | ------- | ------- | ----------- |
| type | `"css"` | Yes | | The output type. |
| dir | String | No | `designsystemet` | The folder where CSS should be saved. |
| cleanDir | Boolean | No | `false` | Delete the files in the folder before creating CSS. See [Cleaning](#cleaning). |
| tokensDir | String | No | `dir` of the `design-tokens` output | The folder containing the design tokens to build CSS from. If neither is set, CSS is created directly from the themes. |
| tailwind | `"v3"`, `"v4"` or `false` | No | `false` | Also generate a `<theme>.tailwind.css` for this Tailwind version. `false` skips it. |

#### types

| Name | Type | Required | Default | Description |
| ---- | ---- | ------- | ------- | ----------- |
| type | `"types"` | Yes | | The output type. |
| dir | String | No | `designsystemet` | The folder where type declarations should be saved. |
| cleanDir | Boolean | No | `false` | Delete the files in the folder before creating type declarations. See [Cleaning](#cleaning). |
| tokensDir | String | No | `dir` of the `design-tokens` output | The folder containing the design tokens to build type declarations from. If neither is set, type declarations are created directly from the themes. |

Creates `types.d.ts`, which adds your theme's colour names to the types in `@digdir/designsystemet-types`, so props like `data-color` only accept your colours.
The deprecated `colors.d.ts` is also created, and will be removed in a future release.

The `css` output no longer creates type declarations. Add `"types"` to `output` to get them.

#### Cleaning

`cleanDir` is `false` by default, so files already in an output's folder are kept. Set `cleanDir: true` on an output whose folder only has files the CLI creates, to also remove files it no longer creates, such as the CSS for a theme you have removed.

Before creating any files, the CLI deletes everything in the folder of each output with `cleanDir: true`, except:

- the design tokens CSS and types are built from (`tokensDir`), unless a `design-tokens` output creates them again in the same run.
- the folders of outputs with `cleanDir: false`.

So with `{ "type": "css", "cleanDir": true, "tokensDir": "designsystemet/design-tokens" }`, the design tokens in `designsystemet/design-tokens` are kept. With a `design-tokens` output, they are deleted and created again, so changes made to them by hand are lost.

To avoid deleting files it shouldn't, the CLI stops with an error, before deleting anything, if a folder it would clean:

- contains the config file.
- is the `tokensDir`, or the folder of an output with `cleanDir: false`.
- is a symlink, or has a symlink on the way to the design tokens or to another output's folder. Cleaning deletes symlinks, and never follows them.

Use another `dir`, or set `cleanDir` to `false` for that output.

#### Without design tokens

By default, `output` is `["css"]`. Without a `design-tokens` output or `tokensDir`, CSS and types are created directly from the themes, without saving any design tokens. Add `"design-tokens"` to `output` to save them as well.

#### Building without themes

`themes` is only needed by outputs that are created from themes. If you already have design tokens, you can leave out `themes` and build from them by setting `tokensDir`:

```json
{
  "output": [
    { "type": "css", "tokensDir": "./design-tokens" },
    { "type": "types", "tokensDir": "./design-tokens" }
  ]
}
```

If an output needs themes and there are none, the CLI stops with an error.

### Migrating from outDir and clean

`outDir` and `clean` are replaced by `output`. When you run the CLI with a config file that uses them, it offers to migrate the file for you.
If you'd rather do it manually, replace `"outDir": "<path>"` with:

```json
{
  "output": [
    { "type": "design-tokens", "dir": "<path>" },
    { "type": "css", "dir": "design-tokens-build", "tokensDir": "<path>" },
    { "type": "types", "dir": "design-tokens-build", "tokensDir": "<path>" }
  ]
}
```

`design-tokens-build` is where `tokens build` saved CSS by default, so your imports keep working. Use the folder you gave `tokens build` with `--out-dir` if you set one. Paths in `output` are relative to the config file, while `tokens build` used paths relative to where it was run, so adjust them if those are different folders.

`cleanDir` is `false` by default, like `clean` was. If you had `"clean": true`, add `"cleanDir": true` to the `design-tokens` output instead, since `clean` only cleaned the design tokens.

A config file without `outDir` and `clean` isn't migrated. It gets the new defaults: only CSS, in `designsystemet`. To keep creating design tokens, CSS and types in the same folders as `tokens create` and `tokens build` did, add the `output` above with `design-tokens` as `<path>`.

### Themes

| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| "themeName" | Object | Yes | The theme you want to define. |

You can have multiple themes, and each theme can have its own colours, border radius, typography, and overrides.

### Theme

| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| colors | Object | Yes | Contains all colours for the theme. |
| borderRadius | Number | No | Base border radius for the theme. |
| typography | Object | No | Contains typography settings for the theme. |
| overrides | Object | No | Contains overrides for colours and severity colours. |

### Typography
| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| fontFamily | String | Yes | The font family for the theme. |

<Alert data-color="info">
If you include `typography` in your theme, `fontFamily` must be defined.
</Alert>

<Alert data-color="warning">
Note that typography is experimental. The config schema may change at any time.
</Alert>

### Colors
| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| "colorName" | String | No | A colour for the theme. |
| neutral | String | Yes | Neutral colour for the theme. |

Colours are defined directly under `colors`, where the key is the colour's name and the value is a hex code.

```json
{
  "primary": "#0062BA",
  "accent": "#1E98F5",
  "neutral": "#1E2B3C"
}
```

### Overrides
| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| colors | Object | No | Contains overrides for individual colour tokens |
| severity | Object | No | Contains overrides for severity colours |
| focus | Object | No | Contains overrides for focus colours |

#### overrides.colors
| Name | Type | Required | Description |
| ---- | ---- | ------- | ----------- |
| "colorName" | Object | No | Overrides for a specific colour |

The `colors` override allows you to customise specific semantic colour tokens for any colour defined in your theme.

Each key in the `colors` object should match a colour name from your colours, or one of the severity colours (`success`, `warning`, `danger`, `info`).

For each colour, you can override individual semantic tokens like `background-default`, `border-subtle`, `text-default`, etc.
Each token override has a `light` and/or `dark` value that points to a hex code.

```json
{
  "overrides": {
    "colors": {
      "primary": {
        "background-default": {
          "light": "#ff0000",
          "dark": "#000fff"
        },
        "text-subtle": {
          "light": "#333333",
          "dark": "#cccccc"
        }
      }
    }
  }
}
```

## Complete Example

```json
{
  "$schema": "node_modules/@digdir/designsystemet/dist/config.schema.json",
  "output": [
    { "type": "design-tokens", "dir": "./designsystemet/design-tokens" },
    { "type": "css", "dir": "./designsystemet", "tokensDir": "./designsystemet/design-tokens" },
    { "type": "types", "dir": "./designsystemet", "tokensDir": "./designsystemet/design-tokens" }
  ],
  "themes": {
    "my-theme": {
      "colors": {
        "primary": "#0062BA",
        "accent": "#1E98F5",
        "neutral": "#1E2B3C",
        "extra1": "#F45F63",
        "extra2": "#E5AA20"
      },
      "borderRadius": 4,
      "typography": {
        "fontFamily": "Inter"
      },
      "overrides": {
        "colors": {
          "primary": {
            "background-default": {
              "light": "#ff0000",
              "dark": "#000fff"
            },
            "text-default": {
              "light": "#00ff00",
              "dark": "#00ffff"
            }
          }
        },
        "severity": {
          "success":  "#28a745",
          "warning": "#ffc107",
          "danger": "#dc3545",
          "info": "#17a2b8"
        }
      }
    }
  }
}
```
