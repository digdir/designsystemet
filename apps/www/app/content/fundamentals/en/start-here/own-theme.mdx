Designsystemet is designed to be used with your own visual identity, including colours and other preferences. With the Designsystemet Theme Builder, you set up your theme in a configuration file. The same file is used in Figma, with the Designsystemet plugin, and in code, with the CLI, so design and code use the same values.

## How to get started

1. Use the [Designsystemet Theme Builder](https://theme.designsystemet.no) to set up your theme. You can set up several themes in the same configuration file under **Edit themes**.

2. Click **Use theme**, and download or copy the configuration file.

3. **Generate CSS for your themes**

- Place `designsystemet.config.json` in your project, in the folder where you want the theme's files.

- Make sure you have Node.js `22.12.0` or later installed. Open a terminal in that folder, and run:

```bash
npx @digdir/designsystemet@latest
```

This generates CSS for your themes, directly from the configuration file, in a folder called `designsystemet`. You can change what is generated, and where, with the [`output`](/en/fundamentals/code/cli-config#output) field in the configuration file. See [Setup](/en/fundamentals/code/setup) for how to use the CSS in your code.

### When you change your theme

Update the configuration file directly in your code, or in the Theme Builder: click **Import config** and paste your configuration file to continue where you left off, and replace `designsystemet.config.json` with the new file afterwards. Then run the command again.

</Tabs.Panel>
<Tabs.Panel value="figma">

3. **Set up your theme in Figma**

- Fetch the component library from [Figma Community (figma.com)](https://www.figma.com/community/file/1322138390374166141/designsystemet-core-ui-kit) (click “Open in Figma”) into your organisation, which needs at least a Pro licence. This will be a copy of the component library, without any connection to the main file.

- In your copy, open the [Designsystemet plugin (figma.com)](https://www.figma.com/community/plugin/1687841992393312960/designsystemet). Upload the configuration file under **Upload config**, or paste it under **Or paste the config**, and click **Import**.

   The plugin creates the variables and styles for your themes, and you should now see all components using your brand colours.

   - Each theme, colour scheme and size is a mode in Figma, and how many modes a collection can have depends on your Figma plan. Read more in [Modes in Figma](/en/fundamentals/figma/modes-in-figma).
   - The fonts in your theme must be available in Figma before you import.
   - The plugin keeps variables, styles and modes it didn't create, and lists them after the import.

### When you change your theme

Update the configuration file in the Theme Builder: click **Import config** and paste your configuration file to continue where you left off. Then import the new configuration file with the plugin. It only changes what has changed, and components using the variables and styles stay connected.

### Icons

To get icons working in Figma, they need to be connected to a library stored in your organisation. See the guide ["Get icons working in Figma"](/en/fundamentals/theme/icons#get-icons-working-in-figma).

## Alternative: Design Tokens and Tokens Studio

If you want to change values the configuration file doesn't support yet, you can generate Design Tokens with [the CLI](/en/fundamentals/code/cli-config#output) and edit all the values in them. The plugin can't import those changes into Figma, so you then sync them with Tokens Studio. See how in [Sync Design Tokens with Tokens Studio](/en/fundamentals/figma/tokens-studio).
