Å bruke config fil med CLI gjer at du kan ha meir kontroll over fargane dine, og kan lettare oppdatere og vedlikehalde dei.

## Kom i gang

Config fila kan heite det du vil, men bruker du `designsystemet.config.json` vil me finne den automatisk om du køyrer kommando i samme mappe. 
Du kan legge den kor du vil i prosjektet ditt. 

Har du plassert fila di ein anna plass, eller med eit anna navn, kan du bruke `--config <path>` i CLI-kommandoar.
Både `designsystemet.config.json` og `designsystemet.config.jsonc` blir funne automatisk, og begge kan innehalde kommentarar og avsluttande komma.

```json
{
  "$schema": "node_modules/@digdir/designsystemet/dist/config.schema.json",
  "themes": {
    "my-theme": {
      "colors": {
        "primary": "#0062BA",
        "neutral": "#1E2B3C",
        "extra1": "#F45F63"
      },
      "borderRadius": 4
    }
  }
}
```

Over har me definert eit tema som heiter `my-theme` med nokre fargar og border radius.
Kvar farge er definert direkte under `colors`, der nøkkelen er namnet på fargen og verdien er ein hexkode, eller eit objekt med fargesteg. Sjå [Colors](#colors).

## Køyre CLI

Køyr CLI-et i same mappe som config fila:

```bash
npx @digdir/designsystemet@latest
```

Dette lagar CSS for alle tema, basert på [`output`](#output)-feltet i config fila. Typedeklarasjonar og design tokens blir berre laga om du legg til ein `types`- eller `design-tokens`-output.

| Val | Forklaring |
| --- | ----------- |
| `-c, --config <path>` | Sti til config fila. |
| `--dry` | Prøvekøyring, ingen filer blir skrivne. |
| `--verbose` | Vis meir utfyllande logg. |
| `--skip-check` | Hopp over automatisk migreringssjekk av config fila. |
| `-y, --yes` | Hopp over spørsmål, til dømes ved migrering av config fila. |

<Alert data-color="info">
Kommandoane `tokens create` og `tokens build` er utdaterte og blir fjerna i ein framtidig versjon. Bruk `designsystemet` med ei config fil i staden.
</Alert>

## Struktur

| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| $schema | Streng | Nei | Sti til JSON schema for validering. Anbefalt: `node_modules/@digdir/designsystemet/dist/config.schema.json`. |
| output | Liste | Nei | Kva CLI-et skal lage, og kvar. Standard er `["css"]`. Sjå [Output](#output). |
| themes | Objekt | Nei | Inneheld alle tema du vil definere. Kvar nøkkel er namnet på temaet. Påkrevd for outputar som blir laga frå tema, sjå [Bygge utan tema](#bygge-utan-tema). |
| outDir | Streng | Nei | **Utdatert:** bruk `output[].dir` i staden. |
| clean | Boolean | Nei | **Utdatert:** bruk `output[].cleanDir` i staden. |

### Output

`output` er ei liste over kva CLI-et skal lage. Kvart element er anten namnet på ein output-type, som brukar standardinnstillingane, eller eit objekt med eigne innstillingar.

Outputane blir alltid laga i rekkjefølgja `design-tokens`, `css`, `types`, same kva rekkjefølgje dei står i. Når CSS og typar blir bygde frå design tokens (med `tokensDir`), må design tokens vere laga først.

Alle stiar er relative til config fila.

```json
{
  "output": [
    { "type": "design-tokens", "dir": "./design-tokens" },
    { "type": "css", "dir": "./css", "tokensDir": "./design-tokens" },
    { "type": "types", "dir": "./types", "tokensDir": "./design-tokens" }
  ]
}
```

#### design-tokens

| Namn | Type | Påkrevd | Standard | Forklaring |
| ---- | ---- | ------- | -------- | ----------- |
| type | `"design-tokens"` | Ja | | Output-typen. |
| dir | Streng | Nei | `designsystemet/design-tokens` | Mappa der design tokens skal lagrast. |
| cleanDir | Boolean | Nei | `false` | Slett filene i mappa før design tokens blir laga. Fjernar filer som ikkje lenger er i bruk. Sjå [Rydding](#rydding). |

#### css

| Namn | Type | Påkrevd | Standard | Forklaring |
| ---- | ---- | ------- | -------- | ----------- |
| type | `"css"` | Ja | | Output-typen. |
| dir | Streng | Nei | `designsystemet` | Mappa der CSS skal lagrast. |
| cleanDir | Boolean | Nei | `false` | Slett filene i mappa før CSS blir laga. Sjå [Rydding](#rydding). |
| tokensDir | Streng | Nei | `dir` i `design-tokens`-outputen | Mappa med design tokens som CSS skal byggast frå. Er ingen av dei sette, blir CSS-en laga direkte frå tema. |
| tailwind | `"v3"`, `"v4"` eller `false` | Nei | `false` | Lagar ei `<tema>.tailwind.css` for denne Tailwind-versjonen. `false` hoppar over det. |

#### types

| Namn | Type | Påkrevd | Standard | Forklaring |
| ---- | ---- | ------- | -------- | ----------- |
| type | `"types"` | Ja | | Output-typen. |
| dir | Streng | Nei | `designsystemet` | Mappa der typedeklarasjonane skal lagrast. |
| cleanDir | Boolean | Nei | `false` | Slett filene i mappa før typedeklarasjonane blir laga. Sjå [Rydding](#rydding). |
| tokensDir | Streng | Nei | `dir` i `design-tokens`-outputen | Mappa med design tokens som typedeklarasjonane skal byggast frå. Er ingen av dei sette, blir typedeklarasjonane laga direkte frå tema. |

Lagar `types.d.ts`, som legg fargenamna i temaet ditt til typane i `@digdir/designsystemet-types`, slik at til dømes `data-color` berre godtek fargane dine.
Den utdaterte `colors.d.ts` blir òg laga, og blir fjerna i ein framtidig versjon.

`css`-outputen lagar ikkje lenger typedeklarasjonar. Legg til `"types"` i `output` for å få dei.

#### Rydding

`cleanDir` er `false` som standard, så filer som alt ligg i mappa til ein output, blir ikkje sletta. Set `cleanDir: true` på ein output der mappa berre har filer som CLI-et lagar, for òg å fjerne filer det ikkje lenger lagar, som CSS-en for eit tema du har fjerna.

Før CLI-et lagar nokon filer, slettar det alt i mappa til kvar output med `cleanDir: true`, bortsett frå:

- design tokens som CSS og typar blir bygde frå (`tokensDir`), med mindre ein `design-tokens`-output lagar dei på nytt i same køyring.
- mappene til outputar med `cleanDir: false`.

Med `{ "type": "css", "cleanDir": true, "tokensDir": "designsystemet/design-tokens" }` blir altså design tokens i `designsystemet/design-tokens` ikkje sletta. Med ein `design-tokens`-output blir dei sletta og laga på nytt, så endringar du har gjort i dei for hand, går tapt.

For å ikkje slette filer det ikkje skal, stoppar CLI-et med ein feil, før noko blir sletta, dersom ei mappe det skal rydde:

- inneheld config-fila.
- er `tokensDir`, eller mappa til ein output med `cleanDir: false`.
- er ei symbolsk lenke (symlink), eller har ei symbolsk lenke på vegen til design tokens eller til mappa til ein annan output. Rydding slettar symbolske lenker, og følgjer dei aldri.

Bruk ein annan `dir`, eller set `cleanDir` til `false` for den outputen.

#### Utan design tokens

Som standard er `output` `["css"]`. Utan ein `design-tokens`-output eller `tokensDir` blir CSS og typar laga direkte frå tema, utan at design tokens blir lagra. Legg til `"design-tokens"` i `output` for å lagre dei òg.

#### Bygge utan tema

`themes` trengst berre for outputar som blir laga frå tema. Har du alt design tokens, kan du sløyfe `themes` og byggje frå dei ved å setje `tokensDir`:

```json
{
  "output": [
    { "type": "css", "tokensDir": "./design-tokens" },
    { "type": "types", "tokensDir": "./design-tokens" }
  ]
}
```

Treng ein output tema og det ikkje finst nokon, stoppar CLI-et med ein feil.

### Migrere frå outDir og clean

`outDir` og `clean` er erstatta av `output`. Når du køyrer CLI-et med ei config fil som brukar dei, tilbyr det å migrere fila for deg.
Vil du heller gjere det manuelt, byt ut `"outDir": "<sti>"` med:

```json
{
  "output": [
    { "type": "design-tokens", "dir": "<sti>" },
    { "type": "css", "dir": "design-tokens-build", "tokensDir": "<sti>" },
    { "type": "types", "dir": "design-tokens-build", "tokensDir": "<sti>" }
  ]
}
```

`design-tokens-build` er der `tokens build` lagra CSS som standard, så importane dine held fram med å verke. Bruk mappa du gav `tokens build` med `--out-dir` om du sette ei. Stiar i `output` er relative til config-fila, medan `tokens build` brukte stiar relative til der det blei køyrt, så juster dei om det er ulike mapper.

`cleanDir` er `false` som standard, slik `clean` var. Hadde du `"clean": true`, legg du i staden til `"cleanDir": true` på `design-tokens`-outputen, sidan `clean` berre rydda design tokens.

Ei config-fil utan `outDir` og `clean` blir ikkje migrert. Ho får dei nye standardverdiane: berre CSS, i `designsystemet`. For å halde fram med å lage design tokens, CSS og typar i dei same mappene som `tokens create` og `tokens build` gjorde, legg til `output` over med `design-tokens` som `<sti>`.

### Themes

| Navn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| "temaNavn" | Objekt | Ja | Temaet du vil definere. |

Du kan ha fleire tema, og kvart tema kan ha sine eigne fargar, border radius, typografi og overrides.

### Theme

| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| colors | Objekt | Ja | Inneheld alle fargar for temaet. |
| borderRadius | Tal | Nei | Base border radius for temaet. |
| typography | Objekt | Nei | Inneheld typografi innstillingar for temaet. |
| overrides | Objekt | Nei | Inneheld overskrivingar for fokusfargar. Å overskrive fargar og severity-fargar her er utdatert, sjå [Overrides](#overrides). |

### Typography
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| fontFamily | Streng | Ja | Font-familien for temaet. |

<Alert data-color="info">
Viss du inkluderer `typography` i temaet ditt, må `fontFamily` vere definert.
</Alert>

### Colors
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| "fargeNavn" | Streng eller objekt | Nei | Ein farge for temaet. |
| neutral | Streng eller objekt | Ja | Nøytral farge for temaet. |
| success, warning, danger, info | Streng eller objekt | Nei | Severity-fargar. Standardfargane blir brukt for dei du ikkje set. |

Fargane blir definert direkte under `colors`, der nøkkelen er fargen sitt namn. Verdien er anten:

- ein hexkode. Heile fargeskalaen blir generert frå han.
- eit objekt med [fargesteg](#fargesteg), der du kan setje kvart steg i skalaen i lys og mørk modus.

```json
{
  "primary": "#0062BA",
  "accent": "#1E98F5",
  "neutral": "#1E2B3C",
  "danger": "#C01B1B"
}
```

#### Fargesteg
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| base-default | Objekt | Ja | Steget `base-default`. `light`-verdien er påkrevd, og er basefargen til skalaen. |
| "stegNamn" | Objekt | Nei | Eitt av dei andre stega i fargeskalaen, sjå [Fargenavn](#fargenavn). |

Kvart steg har ein `light`- og/eller `dark`-verdi som er ein hexkode.

```json
{
  "accent": {
    "base-default": { "light": "#0062BA", "dark": "#4D9BE0" },
    "border-default": { "light": "#5A8BC4" },
    "background-tinted": { "light": "#E8F1FB", "dark": "#0B1D30" }
  }
}
```

`base-default.light` er basefargen, den same som hexkoden du elles ville gitt fargen. Alle steg og modusar du ikkje set, blir genererte frå han.
Over får `accent` skalaen som blir generert frå `#0062BA`, bortsett frå verdiane som er sette. `border-default` i mørk modus blir til dømes framleis generert.
Set du `base-default.dark`, endrar det berre dette steget i mørk modus. Dei andre stega i mørk modus blir framleis genererte frå `base-default.light`.

[Temabyggeren](https://theme.designsystemet.no) eksporterer fargane du har justert på denne forma, med berre stega du har endra. Andre fargar blir eksporterte som hexkodar.

Severity-fargane (`success`, `warning`, `danger`, `info`) blir sette på same måte, direkte under `colors`.

<Alert data-color="warning">
Fargar du set sjølv, blir ikkje justerte for å oppfylle kontrastkrav. Du må sjølv passe på at dei fungerer og har god nok kontrast, både i lys og mørk modus. Sjå [Kontrast](/no/fundamentals/theme/colors#kontrast).
</Alert>

### Overrides
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| colors | Objekt | Nei | **Utdatert:** set [fargestega](#fargesteg) på fargen i `colors` i staden. |
| severity | Objekt | Nei | **Utdatert:** set severity-fargen i [`colors`](#colors) i staden. |
| linkVisited | Objekt | Nei | **Utdatert:** style `.ds-link:visited` i staden. |
| focus | Objekt | Nei | Inneheld overskrivingar for fokus fargar |

`overrides.colors` og `overrides.severity` verkar framleis. Er ein farge sett både i `colors` og i `overrides`, er det `overrides` som gjeld.

#### overrides.colors
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| "fargeNavn" | Objekt | Nei | Overskrivingar for ein spesifikk farge |

<Alert data-color="warning">
`overrides.colors` er utdatert. Set [fargestega](#fargesteg) på fargen i `colors` i staden.
</Alert>

Overstyringen av `colors` lar deg tilpasse spesifikke semantiske fargetokens for kvar farge som er definert i temaets.

Kvar nøkkel i `colors`-objektet skal samsvare med eit fargenavn frå fargane dine, eller ein av severity-fargane (`success`, `warning`, `danger`, `info`).

For kvar farge kan du overstyre individuelle semantiske tokener som `background-default`, `border-subtle`, `text-default` osv.
Kvar tokenoverstyring har ein `light` og/eller `dark` verdi som peikar til ein heksadesimal kode. Sjå [Fargenavn](#fargenavn).

```json
{
  "colors": {
    "dominant": "#0062BA"
  },
  "overrides": {
    "colors": {
      "dominant": {
        "background-default": {
          "light": "#ff0000",
          "dark": "#000fff"
        }
      }
    }
  }
}
```

For å flytte dette til `colors`, byt ut hexkoden med fargesteg, og legg hexkoden i `base-default.light`:

```json
{
  "colors": {
    "dominant": {
      "base-default": { "light": "#0062BA" },
      "background-default": { "light": "#ff0000", "dark": "#000fff" }
    }
  }
}
```

#### overrides.severity
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| "fargeNavn" | Streng | Nei | Hex-farge som skal settast som base |

<Alert data-color="warning">
`overrides.severity` er utdatert. Set severity-fargen direkte i `colors` i staden, til dømes `"danger": "#C01B1B"`.
</Alert>

Overstyringen av `severity` lar deg tilpasse fargane som blir brukt for severity, som er `success`, `warning`, `danger` og `info`.

#### overrides.linkVisited
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| light | Streng | Nei | Hex-farge for besøkte lenker i lyst tema |
| dark | Streng | Nei | Hex-farge for besøkte lenker i mørkt tema |

#### overrides.focus
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| inner | Objekt | Nei | Inneheld fargar for indre fokus |
| outer | Objekt | Nei | Inneheld fargar for ytre fokus |

##### overrides.focus.(inner|outer)
| Namn | Type | Påkrevd | Forklaring |
| ---- | ---- | ------- | ----------- |
| light | Streng | Nei | Hex-farge for indre fokus i lyst tema |
| dark | Streng | Nei | Hex-farge for indre fokus i mørkt tema

## Komplett Eksempel

```json
{
  "$schema": "node_modules/@digdir/designsystemet/dist/config.schema.json",
  "output": [
    { "type": "design-tokens", "dir": "./designsystemet/design-tokens" },
    { "type": "css", "dir": "./designsystemet", "tokensDir": "./designsystemet/design-tokens" },
    { "type": "types", "dir": "./designsystemet", "tokensDir": "./designsystemet/design-tokens" }
  ],
  "themes": {
    "my-theme": {
      "colors": {
        "primary": {
          "base-default": { "light": "#0062BA", "dark": "#4D9BE0" },
          "border-default": { "light": "#5A8BC4" },
          "background-tinted": { "light": "#E8F1FB", "dark": "#0B1D30" }
        },
        "accent": "#1E98F5",
        "extra1": "#F45F63",
        "neutral": "#1E2B3C",
        "extra2": "#E5AA20",
        "success": "#28a745",
        "warning": "#ffc107",
        "danger": "#dc3545",
        "info": "#17a2b8"
      },
      "borderRadius": 4,
      "typography": {
        "fontFamily": "Inter"
      }
    }
  }
}
```
