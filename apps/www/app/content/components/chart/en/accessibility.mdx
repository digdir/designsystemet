Charts are hard to make accessible, because the information is in the shapes. Chart never replaces the table, so the chart you see is the table, only drawn differently. This gives screen reader users access to all the numbers, but you still have to make sure everyone else gets the exact numbers and the message of the chart.

### What you need to check

- **Let everyone get the numbers:** A chart only shows approximate values. Add a control to [switch between chart and table](/en/components/docs/chart/code), show the values with `data-show-values`, or show the same table elsewhere on the page. Without this, the exact values are only available to screen reader users. WCAG: [1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html) and [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html)
- **Describe the message:** A table gives access to the numbers, not to the conclusion. Write the most important finding as text next to the chart, and connect it to the table with `aria-describedby`. WCAG: [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG21/Understanding/non-text-content.html)
- **Title:** Always use `<caption>`. Screen readers read the title first, so users can decide whether they want to read the table.
- **Headers:** Use `<th scope="row">` for the category in each row, and `<th scope="col">` in `<thead>` for each series. The first header in `<thead>` is visually hidden, but must still have text. WCAG: [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html)
- **Language:** Set `lang` on the page. It decides how the numbers in the table are read and how the axis is formatted.
- **Your own colors:** If you change colors or patterns, make sure every series has at least 3:1 contrast against the background, and that series can be told apart without color. WCAG: [1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html)
- **Many series:** Series that share a color are told apart by pattern or shape only. This gets harder to see the more series you have and the smaller the columns are. Use as few series as possible.
- **Small screens and zoom:** Test with your own data at 320 pixels width and at 200 % zoom. Values and category names can overlap or be hidden when there is too little space. Use `bar`, fewer categories or the table if they do not fit.

### Handled by the design system

- The table is kept as a table for screen readers, with title, column headers and row headers. Table roles are added to the elements, since browsers have removed table semantics when the layout of a table is changed with CSS
- Nothing in the chart requires mouse, hover or focus
- The two default colors have at least 3:1 contrast against each other and against the background in all themes, and so do the grid lines
- Areas are always stacked, so no series is hidden behind another
- Series with the same color have different patterns in columns, bars and areas, and different point shapes and dashes in lines
- Pie and donut charts always show the table as a legend with the values, and slices next to each other never look the same when there are six rows or fewer
- Values inside stacked segments have their own background, and are hidden if they do not fit
- The table is shown as a regular table until the JavaScript is loaded
- Missing title or headers give a warning in the console

### Not yet verified

- Screen readers: NVDA, JAWS, VoiceOver and TalkBack have not been tested
- Firefox and Safari have not been tested
- Forced colors mode (Windows contrast themes) and print have rules, but have not been tested
- Text spacing and zoom have not been tested systematically
