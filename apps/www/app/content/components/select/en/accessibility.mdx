## What you need to check

**The field must have a visible label.**

Screen readers must present the label, help text, and error messages when the field receives focus.

You can use [Field](/en/components/docs/field/overview) to connect the label, description, and error messages.

<span data-size="sm">
	WCAG: [1.3.1 Info and relationships (W3C)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships)
</span>

<Divider/>

\
**The field must have a clear accessible name that matches the visible label.**

The accessible name must contain the visible text that describes the field. This allows users of speech recognition and screen readers to refer to the field using the same name shown on screen.

<span data-size="sm">
	WCAG: [2.5.3 Label in Name (W3C)](https://www.w3.org/WAI/WCAG21/Understanding/label-in-name.html)
</span>

<Divider/>

\
**Required fields must be clearly marked.**

Users must easily understand which fields must be filled in. Follow the [pattern for required and optional form fields](/en/patterns/required-and-optional-fields).

<span data-size="sm">
	WCAG: [3.3.2 Labels or Instructions (W3C)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)
</span>

<Divider/>

\
**Error messages must be clearly linked to the correct field and explain how to fix the error.**

The error message must make it clear which field contains an error, what is wrong, and how the user can fix it. Avoid generic messages such as “Error” or “Invalid value”. Use specific messages instead, for example “The email address must contain @”.

See the [pattern for user-triggered error messages](/en/patterns/errors) for recommendations on when and how error messages should be shown.

<span data-size="sm">
	WCAG: [3.3.1 Error Identification (W3C)](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) and [3.3.3 Error Suggestion (W3C)](https://www.w3.org/WAI/WCAG21/Understanding/error-suggestion.html)
</span>

<Divider/>

\
**The first option must not be used instead of a label or to show important information.**

After users have made a choice, they must still be able to understand the context the choice belongs to. Give the field a clear label, for example “Select country”, and use a description for additional guidance if needed.

<span data-size="sm">
	WCAG: [3.3.2 Labels or Instructions (W3C)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)
</span>

<Divider/>

\
**Use the correct autocomplete value when the field concerns the user themselves.**

The correct autocomplete makes it easier to fill in forms and is required for fields that concern the user’s own personal information. See [Purpose of input](/en/components/docs/textfield/overview#purpose-of-input) for when and how to use it.

<span data-size="sm">
	WCAG: [1.3.5 Identify Input Purpose (W3C)](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html)
</span>

## Do not use a disabled state
Avoid using the disabled (`disabled`) state. Consider instead whether you need to show the field at all, or whether you can present the information as plain text or use `readOnly`.

## Test with a Keyboard

**Verify that you can**

- reach the select using <kbd>Tab</kbd>
- open the list using <kbd>Space</kbd> on macOS
- open the list using <kbd>Enter</kbd> on Windows
- navigate between and highlight options using <kbd data-icon>↓</kbd> and <kbd data-icon>↑</kbd>
- select an option using either <kbd>Enter</kbd> or <kbd>Space</kbd>
- move to the first option in the list using <kbd>Home</kbd>
- move to the last option in the list using <kbd>End</kbd>
- jump to the first option that starts with a typed character
- close the list using <kbd>Escape</kbd>
