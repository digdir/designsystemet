## What you need to verify yourself

**Each tab must have a unique and accessible name**

Make sure each individual tab has a clear, accessible, and meaningful name.

\
**Avoid using icons alone without text**

Try to avoid using icon-only tabs. If icon-only tabs are necessary, make sure each tab has an accessible, meaningful name. Ensure that the content is accessible, for example through an accessible tooltip. If you use icons alongside text, ensure they are marked as decorative or have their own accessible title.

<span data-size="sm"> 
WCAG: [1.1.1 Non-text Content (W3C)](https://www.w3.org/WAI/WCAG21/Understanding/non-text-content)
</span>

## Test with a keyboard

**Verify that you can:**
- reach the tab using <kbd>Tab</kbd>
- use the arrow keys to navigate between tabs
- move focus to the first tab using <kbd>Home</kbd>
- move focus to the last tab using <kbd>End</kbd>
- activate the tab using both <kbd>Space</kbd> and <kbd>Enter</kbd>
- navigate to the content (`tabpanel`) using <kbd>Tab</kbd>

<span data-size="sm"> 
WCAG: [2.1.1 Keyboard (W3C)](https://www.w3.org/WAI/WCAG21/Understanding/keyboard)
</span>

## Handled by the design system

- Correct roles on all elements with `role="tab"`, `role="tablist"`, and `role="tabpanel"`.
- Correct state on all elements with `aria-selected`.
- Correct linking between elements with `aria-controls` and `aria-labelledby`.
- Color contrast is handled by the design system's color system. If you deviate from the recommended color tokens, verify that the combination of text and background colors meets the contrast requirements for the tabs.
- Sizing and scaling are handled by the design system's sizing system. If you deviate from it, verify that tabs remain usable when text is resized or when screen magnification is used, without loss of information or functionality.
