Your theme starts as a config file, made in the [theme builder](https://theme.designsystemet.no). That file now goes further: the theme builder can manage all your themes in it, a new version of the Figma plugin brings it into your Figma file, and the CLI creates everything your code needs from it with a single command.

## Several themes in the theme builder

Many organisations need more than one theme, for example for different services or brands. The theme builder now lets you work on all of them in one config:

- **Import your config.** Click **Import config**, paste your config file, and choose the theme to start with. The other themes come along.
- **Switch between themes** with the **Theme** menu in the toolbar.
- **Add, rename and delete themes** under **Edit themes**. A new theme starts as a copy of the one you're on.
- **Keep the colors in step.** Adding, renaming or deleting a color does it in all your themes, while each theme keeps its own color values.
- **Get one config for all your themes.** **Use theme** gives you the config with every theme, ready for the Figma plugin and the CLI, and you choose which theme's CSS to view or download.

Your themes are kept in the page's address, so you can bookmark the page or share it to continue later.

## A new Figma plugin is on its way

The new plugin imports your config into a Figma file, as the variables and styles that the components in Designsystemet's Figma library use. Upload the config from the theme builder, or paste it, and click **Import**.

- **Creates everything your theme needs.** Variable collections and modes for your themes, color schemes and sizes, variables, text styles and effect styles.
- **Updates what's already there.** Variables and styles are matched by name, so the layers that use them stay connected when you change your theme and import again.
- **Keeps what you've made.** The plugin keeps track of what it creates, and only deletes what it created itself. Variables and styles you've added, or renamed and duplicated from the import, are kept, and the plugin lists the ones that aren't in the config.
- **Only changes what has changed.** Importing an updated config only writes what's different, so importing again is quick, and an unchanged config changes nothing.
- **Matches your code.** Each variable shows the CSS variable it's built as in code, so developers see the right names in Dev Mode. Variables are also only suggested where they belong, such as color variables for fills.
- **Tells you what happened.** After the import, you get a list of what was created, updated and deleted, and of anything that couldn't be imported. If a font in the config isn't available in Figma, the plugin stops before changing anything.

Each theme, color scheme and size is a mode in Figma, and how many modes a collection can have depends on your Figma plan. Check that yours allows enough for your config.

The plugin imports what's in the config file. If you've changed the design tokens in ways the config can't describe, the plugin can't bring those changes into Figma. Then you can [sync the design tokens with Tokens Studio](/en/fundamentals/figma/tokens-studio) instead.

We'll let you know when the new plugin is published in Figma Community.

## One command for your theme in code

Until now, getting a theme into code took two commands, `tokens create` and `tokens build`, each with its own options. Now you run the CLI in the folder with your `designsystemet.config.json`:

```bash
npx @digdir/designsystemet@latest
```

This creates CSS for all your themes, directly from the config file. What it creates, and where, is set by the new `output` field in the config file.

### The output field

`output` is a list of what the CLI should create. If you leave it out, you get CSS:

```json
"output": ["css"]
```

| Output | Creates | Default folder |
| ------ | ------- | -------------- |
| `css` | A CSS file for each theme | `designsystemet-theme` |
| `types` | Type declarations for your colors, `types.d.ts` | `designsystemet-theme` |
| `design-tokens` | Design tokens for your themes | `design-tokens` |

Write an output as an object instead of a name to change its settings, for example to choose its folder with `dir`, or to also create a Tailwind file with `tailwind`:

```json
{
  "$schema": "node_modules/@digdir/designsystemet/dist/config.schema.json",
  "output": [
    { "type": "css", "tailwind": "v4" },
    "types"
  ],
  "themes": {
    "my-theme": {
      "colors": {
        "accent": "#0062BA",
        "neutral": "#24272B"
      }
    }
  }
}
```

A few things to know:

- **Design tokens are optional.** You don't need them to get your theme into Figma, since the plugin imports the config directly. Add `"design-tokens"` to `output` if you've changed the design tokens in ways the config can't describe, or [sync them with Tokens Studio](/en/fundamentals/figma/tokens-studio). The CSS and types are then built from the design tokens.
- **Each output empties its folder** before creating its files. Set `"cleanDir": false` on an output to keep the files that are already there.
- **The CSS no longer includes type declarations.** Add `"types"` to `output` to get them, as in the example above.
- **With `"tailwind": "v4"`**, Tailwind's utility classes use the `--ds-*` variables directly, so `data-color`, `data-color-scheme` and `data-size` apply to them too. `"v3"` creates the same Tailwind file as before.

See [the CLI documentation](/en/fundamentals/code/cli-config#output) for all the settings.

### Moving from tokens create and tokens build

`tokens create` and `tokens build` still work, but they are deprecated and will be removed in a future version. So are the `outDir` and `clean` fields in the config, which `output` replaces.

You don't have to change your config by hand. When you run `designsystemet` with a config file that uses `outDir` or `clean`, the CLI offers to update it to `output` for you. To do it yourself, see [migrating from outDir and clean](/en/fundamentals/code/cli-config#migrating-from-outdir-and-clean).

The updated config works the same as before: it still creates design tokens, and saves CSS and types in `design-tokens-build`, so your imports keep working. Once you've checked that you don't need the design tokens, you can remove `"design-tokens"` from `output`.
