`Search` is deprecated and will be removed in the next major version of Designsystemet. Your code still works for now, but your editor will mark the component as deprecated.

Why are we doing this? And what should you do if you're using it?

At the bottom of this article, you'll find examples you can copy to make your own search field.

## Why are we removing `Search`?

A search field looks simple, but there are many ways to make one. Some services want a search button, others only an icon. Some search as you type, others when you press <kbd>Enter</kbd>. Some show suggestions, others go straight to the results. And a search field in a header often looks quite different from one in a form.

`Search` made many of these choices for you. It decided where the icon goes, how the clear button behaves, and how the search button is attached to the field. When your needs were different, you ended up working against the component instead of with it.

We think these choices belong to you. You know your users and your content best. So instead of one component with fixed behaviour, we'd rather give you the building blocks:

- **`Input` with `type="search"`** gives you a search field that screen readers announce as a search field, and that shows a search key on mobile keyboards.
- **`Button`** to submit the search.

## What should you do if you're using it?

You don't need to change anything right away, but you should switch before the next major version.

In many cases, all you need is an `Input` with `type="search"` inside a `Field` with a `Label`.

If you want a search button, a search icon or a clear button in the field, you'll find examples at the bottom of this article. It's a small amount of CSS that you can copy and change to suit your needs.

| Before          | After                                          |
| --------------- | ---------------------------------------------- |
| `Search`        | A `<form>` or `<div>` with your own class name |
| `Search.Input`  | `Input` with `type="search"`                   |
| `Search.Button` | `Button` with `type="submit"`                  |
| `Search.Clear`  | `<button>` with `type="reset"`                 |

## Examples

In [this CodeSandbox (codesandbox.io)](https://codesandbox.io/p/sandbox/9jhssd), you'll find examples of search fields made with our React components: with a search icon, with a visible label, with a search button and with a clear button.

The styles are in the file `search.css` in the sandbox. It has everything `Search` did, in one file. To use it:

1. Copy `search.css` into your project, and import it after `@digdir/designsystemet-css`.
2. Add the class `search` to a `<form>` or `<div>` around your `Input` and `Button`. The class name is just an example, so feel free to use one that fits your project.
3. Give the search field a name. A visible label is best, but `aria-label` is fine when it's obvious what the field is for, like a search field in the header.

If you want a clear button, use a `<button type="reset">` inside a `<form>`, and give the field a `placeholder`. You can use `placeholder=" "` if you don't want any placeholder text. The comment at the top of `search.css` explains the rest.
