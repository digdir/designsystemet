Temaet ditt starter som en config-fil, laget i [temabyggeren](https://theme.designsystemet.no). Nå kommer du lenger med den samme filen: en ny versjon av Figma-pluginen henter den inn i Figma-filen din, temabyggeren kan håndtere alle temaene dine i den, og CLI-et lager alt koden din trenger fra den, med én kommando.

## En ny Figma-plugin er på vei

Få temaet ditt inn i Figma i én operasjon. Last opp config-filen fra temabyggeren til den nye Designsystemet-pluginen, så lager den alle variablene og stilene komponentene i Figma-biblioteket til Designsystemet bruker. Når temaet endres, importerer du det på nytt: bare det som er endret blir oppdatert, lagene som bruker det forblir koblet, og det du har laget selv blir beholdt.

Les mer om [hva Figma-pluginen gjør, og hva den ikke kan importere ennå](/no/fundamentals/figma/plugin). Vi gir beskjed når den er publisert i Figma Community.

## Flere temaer i temabyggeren

Mange virksomheter trenger mer enn ett tema, for eksempel for ulike tjenester eller merkevarer. Nå kan du jobbe med alle i én config i temabyggeren:

- **Importer config-filen din.** Klikk **Importer config**, lim inn config-filen, og velg temaet du vil starte med. De andre temaene blir med.
- **Bytt mellom temaer** med **Tema**-menyen i verktøylinjen.
- **Legg til, gi nytt navn til og slett temaer** under **Rediger temaer**. Et nytt tema starter som en kopi av det du står i.
- **Hold fargene i takt.** Når du legger til, gir nytt navn til eller sletter en farge, skjer det i alle temaene, mens hvert tema beholder sine egne fargeverdier.
- **Få én config for alle temaene.** **Ta i bruk tema** gir deg config-filen med alle temaene, klar for Figma-pluginen og CLI-et, og du velger hvilket tema du vil se eller laste ned CSS-en for.

Temaene dine ligger i adressen til siden, så du kan lagre siden som bokmerke eller dele den for å fortsette senere.

## Én kommando for temaet ditt i kode

Til nå har det tatt to kommandoer å få et tema inn i koden, `tokens create` og `tokens build`, med hver sine valg. 

Nå kjører du CLI-et i mappen med `designsystemet.config.json`:
```bash
npx @digdir/designsystemet@latest
```

Dette lager CSS for alle temaene dine, direkte fra config-filen. 
Hva det lager, og hvor, bestemmer du med det nye `output`-feltet i config-filen.

### Output-feltet

`output` er en liste over hva CLI-et skal lage. Hvis du utelater det, får du CSS:

```json
"output": ["css"]
```

| Output | Lager | Standardmappe |
| ------ | ----- | ------------- |
| `css` | En CSS-fil for hvert tema | `designsystemet` |
| `types` | Typedeklarasjoner for fargene dine, `types.d.ts` | `designsystemet` |
| `design-tokens` | Design tokens for temaene dine | `designsystemet/design-tokens` |

Skriv en output som et objekt i stedet for et navn for å endre innstillingene, for eksempel for å velge mappe med `dir`, eller for å også lage en Tailwind-fil med `tailwind`:

```json
{
  "output": [
    { "type": "css", "tailwind": "v4" },
    "types"
  ],
  "themes": {
    "mitt-tema": {
      "colors": {
        "accent": "#0062BA",
        "neutral": "#24272B"
      }
    }
  }
}
```

Dette er greit å vite:

- **Design tokens er valgfrie.** Du trenger dem ikke for å få temaet ditt inn i Figma, siden pluginen importerer config-filen direkte. Legg til `"design-tokens"` i `output` for også å lagre dem, så blir CSS-en og typene bygget fra dem. Hvis du har endret design tokens på måter config-filen ikke kan beskrive, bygger du CSS-en fra dem med `tokensDir` og [synkroniserer dem med Tokens Studio](/no/fundamentals/figma/tokens-studio).
- **Hver output tømmer mappen sin** før den lager filene sine. Sett `"cleanDir": false` på en output for å beholde filene som allerede ligger der.
- **CSS-en har ikke lenger typedeklarasjoner.** Legg til `"types"` i `output` for å få dem, som i eksempelet over.
- **Med `"tailwind": "v4"`** bruker Tailwind-klassene `--ds-*`-variablene direkte, så `data-color`, `data-color-scheme` og `data-size` gjelder for dem også. `"v3"` lager den samme Tailwind-filen som før.

Se [dokumentasjonen for CLI-et](/no/fundamentals/code/cli-config#output) for alle innstillingene.

### Fra tokens create og tokens build

`tokens create` og `tokens build` virker fortsatt, men de er utfaset og blir fjernet i en senere versjon. Det samme gjelder feltene `outDir` og `clean` i config-filen, som `output` erstatter.

Du trenger ikke endre config-filen for hånd. Når du kjører `designsystemet` med en config-fil som bruker `outDir` eller `clean`, tilbyr CLI-et å oppdatere den til `output` for deg. For å gjøre det selv, se [migrering fra outDir og clean](/no/fundamentals/code/cli-config#migrere-frå-outdir-og-clean).

Den oppdaterte config-filen virker som før: den lager fortsatt design tokens, og lagrer CSS og typer i `design-tokens-build`, så importene dine fortsetter å virke. Når du har sjekket at du ikke trenger design tokens, kan du fjerne `"design-tokens"` fra `output`.
